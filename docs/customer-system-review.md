## 本轮已落地：商户线路

- 商户列表增加“线路”，支持全部线路/未分配/1—16号线筛选，能与街道和关键词组合；重置同时清空线路条件。
- 新增、查看、编辑、导出使用同一份16线字典。未确定归属时允许未分配。
- 初始商户的归属完全模拟；旧缓存不强行猜测，缺少字段时迁移为未分配，保留既有收运和排班数据。
- 这里是商户的运营归属，不自动改写现有线路点序、车辆排班和历史称重。与几何路径的对应关系另行确认，避免“改档案”连带改历史。
- 不增加页面，不改变Arco的表格、筛选、抽屉和表单交互。

## 建议优化优先级

| 优先级 | 我们目前的不足 | 建议 | 本轮状态 |
| --- | --- | --- | --- |
| P0 | 商户只能按街道识别，缺少客户习惯的16线运营归属 | 增加线路展示、组合筛选、维护和导出 | 已实现 |
| P1 | 单一商户名称不足以同时查营业执照名称和门店招牌 | 增加“执照名称/招牌名称”语义独立字段，统一搜索；不把现有证照附件说明当作执照名称 | 建议，待确认字段与迁移规则 |
| P1 | 当前“重量”容易与客户过磅总量被当成同一个指标 | 独立车辆过磅账（流水、毛皮净重、时刻），与逐桶收运账分别展示，后续按趟次核对差额 | 后续用户已明确地磅需求：已实现日期＋车辆比对与原始地磅抽屉；趟次/跨日匹配仍待确认，详见地磅比对需求 |
| P1 | 桶规格只在资产详情可见，客户台账习惯分120L/240L查看 | 在商户台账/报表补规格分组；注意“投放桶数”和“实际翻桶次数”不同，不用资产数当作收运桶次 | 建议，待逐桶事件的规格快照确认 |
| P1 | 当前不便追查某个商户最近一次服务及长期未收 | 增加最后收运时间、运营/停止收运筛选及停运原因；历史记录仍可查，不能把今天未完成直接认作漏收 | 建议，先确认停运状态与经营/签约的对应关系 |
| P1 | 原型缺少可核对的称重图片/凭证链路 | 从采集/过磅详情打开对应凭证，按事件查，不先做全量图片下载 | 建议；本次只确认客户存在下载入口，未验证图片可用性 |
| P2 | 地图没有客户首页的车队/人员查询、最后在线时间 | 地图侧栏强化对象查询与最后上报，区分离线和未出勤；保留现有Arco控件 | 建议，待定位事件口径确认 |
| 待确认 | 客户分餐厨、炸货油、地沟油，而原型以餐厨为主 | 确认本项目是否覆盖两类油脂，再决定分类与专用台账；不机械扩展业务 | 未扩范围 |
| 暂不复制 | 客户台账含供货方、结算、合规票据 | 收运端保留必要关联即可，先确认职责与接口，避免复制一套财务系统 | 未扩范围 |

## 设计判断

应借鉴客户的运营词汇、按线路管理商户、按对象逐层查账和凭证追溯。保留Arco交互和已有模拟功能；后续按用户要求将商户与资产拆分为独立页面。除明确要求的商户线路外，本轮把其余差距列为可评审的优化项，避免把受限账号能看到的页面误当成客户完整业务，或擅自引入新的结算、过磅和油脂需求。

后续更新：用户已明确要求新增地磅数据与准确率，已按新需求完成模拟原型，详见[地磅比对需求](./weighbridge-requirements.md)。上表其余建议仍未默认扩展。
