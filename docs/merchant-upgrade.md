# 融涞系统商户管理升级范围

## 基线与原则

融涞系统指用户指定的 car.r10iot.com 智慧环卫模块。本轮是现有系统优化升级，不是另做完整平台。只为明确调整设计原型，新增/调整标红。客户数字化收运系统仅用于参考运营习惯，不作为融涞已经具备功能的证据。

已只读打开融涞商户列表和编辑窗口确认：原有商户名称、类型、经营状态、机构、联系方式、面积、预估垃圾量、地址、备注、120/240/660L配桶和最多5张照片功能存在。没有修改或保存线上数据。本轮可见窗口未见线路字段。

## 本次交付

| 位置 | 升级内容 | 原型表现 |
| --- | --- | --- |
| 列表 | 新增线路列 | 标题“线路·新增”及值标红 |
| 筛选 | 新增线路筛选 | 红色线路控件，含全部线路、未分配、1—16号线 |
| 编辑 | 增加线路归属 | 右侧展示完整原有表单及红色线路单选，可模拟保存/取消 |
| 详情 | 展示线路 | 标签与值标红 |
| 导出 | 导出增加线路名称 | 继承导出动作，当前筛选全量导出，不限当前分页 |
| 产品需求说明 | 字段及验收规则 | 新增规则标红 |

旧商户归属为空时显示未分配，不强制分配。线路改动不追改历史收运、不改写已有作业路径或排班，不引入派单。原有商户资料在列表和右侧详情/编辑完整保留，使用普通颜色作为演示上下文；包括机构、联系方式、面积、预估量、地址、备注、120/240/660L配桶和照片区域。现有表单可本地模拟保存/取消，配桶数量独立模拟保存，不反写RFID实物资产；照片使用可预览占位图及说明，不上传真实附件。新增/删除/导入流程仍沿用现网；正式开发在原有表单中增加线路，不删原有信息。

## 其他内容处理结论

- 车辆与设备：移除原型菜单、路由、页面及对应页内需求，现场已有其它模块负责；收运报表使用的模拟车辆基础数据保留。
- 垃圾桶管理、收集点管理：融涞已有独立资产功能。此前原型的页面拆分、原生交互及基础字段不算本次新增；编号/归属校验只是原型保护，未证实现网缺失，不能据此宣称升级。暂无明确需交付的新优化点，从升级原型移除。底层模拟桶/点及关系继续供收运使用。
- 商户其它字段：现有功能继续沿用，不标成新需求。保留已有信息作为完整演示上下文；不把签约状态、额外统计卡、今日作业列表、配桶重构或执照/招牌拆分纳入新增需求。
- 其它业务页面：本轮暂保留，未在这次商户评审中逐页裁剪或完成标红；后续按同一原则单独评审。

## 验收

1. 商户列表、筛选、查看、编辑的线路位置可清楚辨认红色与“新增”含义。
2. 原有字段完整显示，机构只读，其它表单字段可模拟编辑保存/取消；非法线路拒绝保存。仅改变线路时，其它原有值应保持一致。
3. 按线路查询后，详情、列表与导出的线路名称一致；重置显示全部。
4. 升级原型不再出现车辆设备或资产管理菜单/页面，原系统对应功能未受影响。

本说明取代之前文档中商户整页重做、三页资产维护的交付范围；原先审查记录仅作历史参考。
