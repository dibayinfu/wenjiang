# 联单管理产品需求设计

状态：已实现单次联单、季度汇总、单位与印章设置的交互原型（#/reports/manifests），含HTML下载和打印另存PDF。正式PDF后台服务、跨用户唯一编号及五联模板尚未实现。依据用户提供的三张图片，不将图片中的真实印章或单位资料复制进模拟数据。不将模板脚注直接作为程序动作或自动报送指令。

## 一、功能入口与交付范围

在作业监管增加「联单管理」入口，仅设一个主页面，页内三个标签：单次联单、季度汇总、单位与印章设置。新功能标红并注明新增；文书预览/下载/打印使用正常黑色版式，红色只用于实际选择的印章，不把原型升级标记打印到正式文件。

支持两类业务文书和一个备选版式：

1. 单次管理联单：依附商户某次已完成收运记录，采用图片1《成都市餐厨垃圾管理联单》。一张业务联单可含该次多条逐桶明细，但只能属于同一商户、同一次收运、同车及同一收运/处理单位组合。
2. 季度统计汇总表：采用图片2《成都市餐厨垃圾收运情况统计（汇总）表》，按自然季度生成，列出产生单位及处理去向。季度内三个月分别列量，同时提供季度合计，避免将表头“吨/月”误写成季度总量。最终表头排版须业务确认。
3. 客户现用五联单：图片3为可选打印模板，不另造一份业务台账。按日期＋车辆＋收运单位＋处理单位选取多家商户记录排版，一行是一家商户的一次收运；同一商户多次收运不默默合并。第一版以图片1、2为必交，五联版式是否作为日常主模板待客户确认。

不扩展派单、结算或自动监管报送。业务文书只证明可追溯的收运/交运事实，不能把已收运重量直接宣称为商户全部产生量。

## 二、单位与印章设置

收运单位、处理单位在联单设置中集中维护；产生单位关联商户档案，不要求运营每次重复填。

| 对象 | 维护字段 | 使用规则 |
| --- | --- | --- |
| 收运单位 | 单位全称、统一社会信用代码（可选）、联系人、启用状态、默认标识 | 可维护多家，设置一个默认，生成时选定并形成快照 |
| 处理单位 | 单位全称、地址、默认接收人、启用状态、默认标识 | 每张单明确处理去向；不是全项目永远只有一家 |
| 产生单位 | 商户ID、用于文书的单位名称、联系人 | 默认使用确认的执照名称；如现有档案只有商户名，预览时明确请核对，不擅自视为执照名 |
| 文书人员 | 填表人、负责人；可选默认收运人、接收人 | 默认值可带入草稿，每次生成前可调整 |
| 印章 | 所属单位、章名称、PNG图像、版本、启用状态、用途说明 | 产生/收运/处理单位分别绑定，不能用收运单位章代替商户章 |

单位列表可新增、编辑、停用；停用不影响历史已生成文书。存在历史引用时不硬删除单位或印章版本。

印章上传：建议透明PNG，限制2MB，校验文件内容和尺寸，提供白底预览和模板落位预览；不直接接收SVG。上传后显式选择所属单位，保存新版本。不得默认从客户截图抠取印章。只演示时使用带“模拟”文字的虚构章。

章位置由模板预设，允许在模板预览中调整位置和大小并保存模板版本，第一版不做自由拖拽文书编辑器。图片中的签字位置保留，单位章不代替收运人/接收人/产生单位签字。

缺少章时允许生成“待签章”打印件，留出纸质签章位置；不得因为上传过某个章就把所有文件自动盖章。选择加盖已配置章时应明确展示单位、版本和作用范围，并在生成确认中勾选；生产版须限制章配置和使用权限、记录操作日志，不新增整套权限管理页面。

## 三、单次联单操作流程

商户报表/逐次收运记录 → 生成联单 → 检查草稿 → 预览 → 确认生成 → PDF下载/打印。

联单管理也可从商户、日期、车牌筛选已完成记录，勾选同一收运事件的原始记录生成草稿。草稿显示来源记录数、总kg及吨值；不可跨商户或随意组合不同趟次。未完成/待核验/重复关联记录不自动入正式单。

| 模板字段 | 来源与规则 |
| --- | --- |
| No. | 正式生成时服务端分配；草稿显示待生成编号 |
| 产生单位 | 所选商户的文书单位名称及该单位章（如有明确授权） |
| 收运单位 | 选定的收运单位及章 |
| 收运车辆、收运人 | 历史收运事件的车辆/人员快照；缺失时人工补全并记录来源 |
| 处理单位、接收人 | 实际处理去向与接收记录；设置中的人名仅作默认，不等于已经接收 |
| 餐厨垃圾量、废弃食用油脂量 | 关联该次有效实收明细分类型汇总，kg转吨，建议保留三位小数 |
| 总量 | 两类重量相加，以未提前舍入的原始kg计算后转换 |
| 收运单位接收日期 | 实际交接时间，不用生成时间代替 |
| 处理单位接收日期 | 实际到厂接收时间，缺失时留待确认，不能使用同步时间冒充 |

当前只有餐厨数据时，油脂显示“未采集/未涉及”，不能把缺失数据填0；明确确认本次无油脂时才填0。界面允许确认“本次不涉及油脂”，记录确认信息。

没有商户级处理接收证据时，不能按各商户重量比例分摊整车地磅量，再称其为实际处置量。商户单以商户实际收运量为依据，整车地磅可作为关联核对证据；未完成处理接收确认的文件标注“待处理单位接收确认”。

正式生成前强制确认：商户、来源事件、垃圾类别和重量、单位及接收信息、签章方式。允许保留缺失接收信息的草稿或待签章件，但不得标成已完成三方交接。

## 四、季度汇总流程与口径

选择年份、自然季度、收运单位 → 统计预览 → 核对异常与去向 → 生成季度汇总 → 下载/打印。

- 产生单位区：按商户分组，分别显示三个月的餐厨/油脂量、季度合计；来源为期间有效完成收运事件，不因是否已经生成单次联单而重复或漏算。可查看哪些记录尚无联单。
- 处理去向区：按处理单位分组统计实际接收/处理量，与上部收运量分开；只有地磅进厂记录时应叫“进厂接收量”，不能直接冒充已处理量，正式报表中的处置量需来源确认。
- 季度按北京时间自然季度边界，分别使用收运事件业务时间和处理接收业务时间；跨季接收自然形成差异，不强行调平。
- 显示源数据条数、待核验/未确认处理记录数、排除原因。季度尚未结束时，允许预览或生成注明“截至某日”的阶段稿，不标成完整季度最终报表。
- 预估量、配桶数量、垃圾桶容量都不能换算成实际重量。未采集油脂时显示未采集，不生成看似完整的油脂统计。
- 批量多页时重复表头、注明第x/y页；产生单位和处理去向各自有小计/总计，末页展示填表人、负责人、填表日期。
- 如需严格沿用图片2的单个“吨/月”栏、不增加三个月栏目，应选择“按月三页＋季度合计附件”方案；最终输出模板在开发前由客户确认，底层数据模型不变。

## 五、编号唯一与防重复生成

建议自动编号（示例仅为新系统建议，不沿用纸质编号冒充原编号）：

- 单次：WJ-LD-20261030-000001。
- 季度：WJ-JB-2026Q3-000001。
- 如需沿用客户CTSY纸质号段，须配置已获确认的独立电子号段及起号，并导入已用号，不能自行从截图推定下一号。

生产版必须由服务端事务/数据库序列分号，并对项目＋完整编号建立唯一约束；不能用浏览器时间戳、前端自增或先查再插保证并发唯一。流水号不因删除或作废而复用，不强求无断号。

生成请求携带幂等键；双击、网络重试返回同一张文件，不再出号。单次来源事件的有效关联建立唯一约束，阻止同一次收运重复生成有效联单；批量原始明细使用关联表逐条约束。五联打印只是同一业务单的不同联次，不重复计算业务量。

季度以项目＋收运单位＋年份季度＋数据范围作为业务键，重复点击打开现有版本。源数据变化时显示“存在未纳入变更”，允许显式生成新修订版；新版本记录原单和修订原因，旧版不覆盖、不删除。

纯前端原型只能保证当前浏览器会话/本地缓存内的演示编号，不能承诺跨用户、跨浏览器的全局唯一。编号唯一性属于生产后台验收项。

## 六、文书状态、快照与更正

保持简单：草稿、已生成、已作废；另设签章/交接状态（待签章、待接收确认、已确认），不要把“已下载/已打印”当成已签收。

正式生成时保存文书快照：来源事件ID及版本、明细重量、商户/单位名称、车辆/人员、业务时刻、印章版本和文件摘要、模板版本、编号、操作者、生成时间。后台更新商户名、单位名、章或源记录，不改历史PDF。

已生成单据不直接编辑；有错则作废并写明原因，再按原单关联重开。重开使用新编号，保留原编号和替代关系；作废件明显加作废标识。季度修订版保留前后版本并标明当前有效版。

列表筛选：单据类型、商户、收运日期/季度、车牌、编号、状态。行操作：查看、下载、打印；草稿可继续编辑，已生成可作废。批量生成先预览清单和异常，不给每个垃圾桶单独出一张业务联单。

## 七、预览、下载、打印

单次用A4纵向，五联横向版式按客户纸张确认；季度长表使用A4并自动分页。生成前预览标“草稿”，正式PDF带固定编号。下载与打印必须来自同一已保存快照，不临时重算。

生产版由服务端统一渲染PDF，嵌入中文字体及印章图，返回带鉴权的文件下载；打印打开同一PDF。浏览器“打印另存为PDF”仅作为原型演示，不冒充已实现的正式PDF下载接口。

五联模板提供联次选择或一次生成五页，每页同一业务编号并明确第几联、交付对象；五联交付对象不能凭截图补齐，待客户提供完整五联样张确认。实际签字可预留纸质签字，上传图片章仅表示图像叠加，不宣称完成可信电子签署。

## 八、开发数据结构与验收

建议最小表：单位、单位印章版本、文书模板版本、联单主表、联单来源关联、文书文件/快照、操作日志。季度快照保存商户/月明细和处理单位/月明细。签章授权与文件访问沿用现有身份体系，原型只做本地模拟。

必须验证：并发不重号、重试不重复出单、同一事件不重复入有效单、作废不复用号码、kg/吨及分类合计守恒、跨季度边界、源数据变化不篡改历史文件、换章不影响旧件、缺少油脂/处理接收时不填假0、长表分页和中文/印章打印完整。

## 九、需客户确认的少量业务项

1. 单次主模板是否采用图片1；图片3五联作为额外打印样式还是日常必用模板？
2. 是否延续CTSY编号，现有纸质号段如何划分，电子联单号是否需要外部登记？
3. 季度表“吨/月”采用分月三列还是三个月分别出表，处置量取进厂接收量还是处理完成量？
4. 处理单位接收时间/接收人和商户油脂数据目前由哪里取得？哪些单位授权使用上传章？

以上不阻止先制作可评审原型：默认图片1单次、图片2按月拆分季度汇总、图片3可选样式；模拟编号与模拟章明确标识。正式模板和正式签章方式需在投入使用前确认。

## 最新范围（取代前文手动和季度方案）

商户报表改为商户联单；按商户＋北京时间日期，每天凌晨01:00自动生成昨日有有效收运记录商户的五联单。多车收运列全车辆，不选择单车代替。新增联单列：当日待生成，已生成查看；展开五个联次并直接下载五页PDF。去掉手动生成及季度联单，保留单位印章设置。原型模拟历史批次，生产后台负责调度、全局唯一和补传修订。原型PDF为Canvas中文栅格页，无服务端依赖，五联共用编号；第四第五联交付方待确认。配置修改不重算历史快照。

最新模板约束：五联严格使用用户确认的附表2《成都市餐厨垃圾管理联单》，保留原表合并关系、底部四项说明、No.及两类重量/日期栏。预览和PDF共用同一画布模板；联次及模拟提示放于表外。未采集油脂量及完整总量、未经确认接收人及接收日期留白，不能擅填0或以批次时间代替。PDF按比例适配A4不拉伸。

最新启用规则：业务设置菜单改为联单设置，默认关闭。开启后才展示固定模板选择、单位与印章配置，商户报表才显示联单列并执行模拟批次；关闭隐藏入口和配置、停止生成，历史快照和设置保留。商户菜单恢复为商户报表。

## 最新实现：租户模板列表

联单设置改为列表，添加/编辑共用抽屉，支持模板名称、说明、开启状态、标题、五联名称、底部说明（280字以内避免溢出）、显示车辆/收运人、收运与处理单位、演示章。列表可预览、复制、启停、删除未引用模板，复制默认关闭。启用替换需确认，同租户同业务互斥。每次保存形成新版本，联单保存完整模板快照，预览/PDF读取历史快照。

旧版设置迁为一个模板，旧历史文书保留。模拟上下文固定为温江演示租户，本地存储键带租户ID；这不是生产权限隔离，生产需服务端强制租户鉴权。成都版式是当前唯一基础样式，字段和内容可配置，不声称支持任意版式。

最新打印规则：一份业务联单对应一张文书、一页PDF；打印时选择5份，各份内容和编号完全相同。移除逐联预览、五页PDF及五个联次名称配置。底部原模板说明保留；重复下载/打印不重新生成编号。历史已下载五页文件不变，新下载统一输出一页。

## 机构配置最终简化

地区版式归平台，机构仅选择地区、维护两家单位与印章、启停及日期缺省策略。机构编辑不再开放标题、底部说明、字段隐藏或人员固定值。温江新模板默认收运单位为山高十方环保能源集团有限公司成都温江分公司，处理单位为成都市温江城投顺源生态环境建设有限公司；已有机构配置不强制覆盖。

司机从收运事件记录保存的车辆司机快照取，不用当前车辆默认司机改写历史；旧记录缺失时待接入。餐厨量及总量均为商户当日有效餐厨实收kg转吨。收运日期自动填写；处理接收默认实际日期，未接入留白，机构可明确选择按收运日期填。时分默认留白，可勾选以00为缺省值，不宣称采集时刻。已生成单据不回填，不覆盖历史文件。

## 最新机构、编号及时间规则

所属机构默认成都市温江城投顺源生态环境建设有限公司，编辑从租户授权SaaS机构目录下拉选择。模板名称从预置模板下拉选择温江顺源联单模板。列表仅显示模板名称、所属机构、开启状态及操作，不显示类型/版本/更新时间；内部保留版本以支撑快照。

展示编号为YYYYMMDD＋0001—9999，按机构及业务日期分配；不同机构允许重号，同机构不重复。业务编号与随机内部文书ID分开。生产建立租户/机构/编号唯一约束及事务序列，达到9999禁止继续生成，不能扩位或回收。原型迁移旧记录仅补展示编号，不改内部ID、重量、单位与章。

新生成文书收运接收时间取该商户当日有效逐桶数据最早collectedAt；处理接收仅填日期，模拟取同车同业务日最早地磅grossAt（旧记录无毛重时间才使用完成过磅时间）。跨日/多趟正式版须按实际交运关联，不凭同车同日证明处置完成。旧文书快照不擅自回填或改写。删除编辑中的时间策略。

表单精简：去掉授权机构提示、说明输入及两段生成规则提示；模板名下显示“系统创建模板”。收运/处置单位默认填写已确认全称。移除章需二次确认，仅改草稿，保存后生效，取消不改章。自动取数及凌晨生成逻辑归商户报表产品需求说明。
