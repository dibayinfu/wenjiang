# 收运坐标数据目录

每个日期使用一个 `YYMMDD` 子目录，保留原导出 JSON 格式。例如 `261117` 表示 2026 年 11 月 17 日。

```text
261117/
  路线261117.json
  收运明细261117.json
```

路线文件也可命名为 `轨迹261117.json`。集齐该日期的明细和轨迹后，即可在“本地数据”模式选择。

## 收集点统一使用完整离线快照

`../collection-point-snapshot.json` 保存从温江 `/api/collectionPoint/mapPoints` 读取的完整业务数据，同时保存 `/api/collectionPoints` 正式档案作为 `registry`，包含 `fenceLnglats`、`fenceRadius`、`fenceId`、坐标系和采集时间。快照不包含账号、Token 或 Cookie。

本地模式的收集点不再使用每日 `商户收集点YYMMDD.json` 的旧登记坐标和零散校正表。所有日期共用这份离线快照，日期只切换明细和轨迹；不登录、不请求真实接口也能显示完整围栏。旧导出文件原样保留作归档与手动导入兼容，不再作为本地模式的地图来源。

快照与在线接口使用同一解析规则：WGS-84 边界转为 BD-09 并保留六位，圆形取转换后边界的外接矩形中心，并采用原始半径；多边形保留真实边界。内部绘制、搜索定位和未匹配判断共用 GCJ-02 几何，百度显示层转换回 BD-09。默认使用原始围栏，手动选取米数时切换为自定义核验圆。

当前快照采集于 2026-11-18，共 224 个收集点（223 个圆形、1 个多边形）。设置中显示快照日期，不能将它解释为所选日期当天的历史围栏。线上和本地均只接受温江机构有效正式档案中的点，并核对收集点 ID、商户 ID 和围栏 ID；名称、地址以正式档案为准，不按名称黑名单或地理范围删点。后续更新快照时，同时更新地图与正式档案的完整响应，保持坐标系、采集时间、`data.totalCount` 和 `registry.totalCount` 正确，不按日期重复保存。

`../collection-point-map-corrections.ts` 仅用于手动导入缺少几何的旧文件兼容。带有效边界的数据优先读取真实几何，不应用旧补丁；缺少真实几何且无法核验的手动文件明确显示参考范围。

## 本地验证与部署

运行 `npm run dev` 查看。GitHub Pages 会随构建发布所引用的 JSON，供能访问站点的人下载。业务数据和快照均集中在本项目的 `src/mock/` 中，不依赖其他项目。
