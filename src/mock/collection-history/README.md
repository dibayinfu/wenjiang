# 收运坐标数据目录

每个日期建一个 `YYMMDD` 子目录，并保留原导出 JSON 格式。例如 `261111` 表示 2026 年 11 月 11 日。

```text
261111/
  路线261111.json
  商户收集点261111.json
  收运明细261111.json
```

路线文件也可命名为 `轨迹261111.json`。新增日期时将目录名和三个文件名的日期一起替换。集齐三个文件后，页面才会显示该日期。

本地放好文件后可用 `npm run dev` 查看。GitHub Pages 会随构建发布这些 JSON，供能访问站点的人下载。提交到发布分支前，请确认数据适合该站点的访问范围。

## 收集点地图坐标校正

2026-11-12 登录真实系统只读核验发现：列表接口导出的 `lng/lat` 与地图接口 `/api/collectionPoint/mapPoints` 的坐标不完全一致。地图接口返回的 `lng/lat` 直接用于 `BMapGL.Point`（BD-09），例如四川交通职业技术学院 A 实际为 `103.81781280217406, 30.695696372735583`，列表导出仍为 `103.831556, 30.694759`。

`../collection-point-map-corrections.ts` 保存当前两个日期中 12 处差异的已核验坐标。历史加载和手动导入共用校正：仅当 `fenceId` 和原始经纬度均匹配时使用地图坐标，再统一转换为 GCJ-02；百度显示层转换回 BD-09。原始 JSON 和原导出坐标保留，详情提示中可核对校正来源。同一围栏后续导出的坐标发生变化时，不套用旧校正。

新点位或新的差异需从真实系统地图接口核验并补充，不能仅凭坐标数值或收运 GPS 自动推测正确位置。缺少坐标的记录仍跳过。
